# Project guide for Claude

Monorepo for one product: a React web app, a React Native (Expo) mobile app,
a Go backend (modular monolith on one EC2 instance), and Terraform for AWS.

## Layout

| Folder     | What                                         | Details              |
|------------|----------------------------------------------|----------------------|
| `web/`     | React + Vite + TypeScript SPA (S3+CloudFront) | `web/CLAUDE.md`      |
| `mobile/`  | Expo (React Native) app, built with EAS       | `mobile/CLAUDE.md`   |
| `backend/` | Go modular monolith, stdlib `net/http`        | `backend/CLAUDE.md`  |
| `devops/`  | Terraform + deploy scripts                    | `devops/CLAUDE.md`   |
| `docs/`    | Product spec, design tokens, architecture     |                      |

Request path: client -> API Gateway (HTTP API) -> VPC link -> Cloud Map -> EC2 :8080.

## Commands (run from repo root)

- `make dev` - backend on :8080 + web on :5173 (web proxies `/api` to backend)
- `make test` / `make lint` - all suites; run both before saying work is done
- `make plan ENV=dev` - preview infra changes
- `make deploy ENV=dev` - infra + backend + web (CI does this on every push to main)

## How to work here

1. **Product first.** Read `docs/product/spec.md` if it exists. If the user
   describes a new idea and there is no spec, use the `kickoff` skill.
2. **Features are vertical slices:** backend module -> typed client in
   `web/src/api.ts` and `mobile/src/api.ts` -> UI. Keep both clients in sync.
3. **Design tokens** live in `docs/design/tokens.json` and are mirrored in
   `web/src/styles.css` and `mobile/src/theme.ts`. Change all three together.
4. **Small commits** with clear messages; CI must stay green.
5. When the user hits friction with this template itself, log it with the
   `template-feedback` skill.

## Guardrails

- Never commit secrets. Runtime secrets go in AWS SSM Parameter Store.
- Never run `apply`/`destroy` against `prod`, or `make destroy` anywhere,
  without the user explicitly asking in this conversation.
- Never hand-edit `mobile/ios` or `mobile/android` (generated by Expo).
- `devops/project.env` is generated by `scripts/bootstrap.sh`; don't edit by hand.
- The example `notes` module and screens are placeholders; replace them once
  the real product exists.
